## 球员对象（现有风格）

```js
{
  n: "球员中文名",
  en: ["English Name", "别名"],
  pos: ["CB"],              // 位置数组，第一个为主位置
  foot: "右",               // 左 / 右 / 双 / null（不确定）
  club: "切尔西",
  nat: "英格兰",
  tags: ["回追型"],          // 只能用现有词表
  pair: [],                 // 可空
  d: "一句话描述；弱点可写在这里",
  // a: {...}                // 只给曼联，不写对手
  // weak: "伤病史"          // 新候选必须给；现有库多数没有，写入前先确认
}
```

## 位置枚举

`GK / CB / LB / RB / LWB / RWB / DM / CM / AM / RM / LM / LW / RW / ST`

位置顺序影响 `scoreFor`：`pos[0]` 是主位置。边后卫/翼卫都可打时，把球队更常用的放前；不要为了排阵硬造位置，若主位置与球队用法不同，在候选 `note` 里写清。

## 惯用脚

`左 / 右 / 双 / null`

- `null` 只用于确实查不到；不要用 `左`/`右` 猜。
- 脚是硬字段，必须有来源（PL / Transfermarkt / FotMob / EA）。
- 门将也填脚；不要留空除非来源没有。

`门线型 / 清球型 / 出球型 / 争顶型 / 拖后型 / 上抢型 / 对抗型 / 回追型 / 左脚中卫 / 套边型 / 内收型 / 翼卫 / 攻击型 / 破坏型 / B2B / 组织8 / 拖后组织 / 节拍器 / 肋部8号 / 多面手 / 全能多面手 / 古典10余晖 / 现代10 / 自由10 / 伪10 / 伪9 / 支点 / 抢点型 / 逼抢9 / 全能9 / 全能9潜力 / 逆足内切 / 顺足下底 / 内锋 / 逆足`

校验器会从 `players.js` 动态读取实际词表；新增标签会被判为阻断问题，需用户确认后才扩词表。

## 弱点词表（候选表用）

`回追慢 / 不参与防守 / 逆足限制 / 防空弱 / 体能掉档 / 怕一对一 / 压迫下失误 / 易失位 / 纪律差 / 伤病史 / 终结效率低 / 待确认`

现有库多数球员没有 `weak`；切尔西新补 5 人已试点写入。新候选必须给 `weak` + `weakNote`（依据/来源），不能留空让用户填。现有球员的 `weak` 未结构化，后续按队补，不要为了统一而给所有人硬编。

## 候选 JSON

```json
{
  "team": "切尔西",
  "form": "3-4-2-1",
  "rows": [
    {
      "n": "埃米·马丁内斯",
      "en": ["Emiliano Martinez", "Dibu"],
      "club": "切尔西",
      "pos": ["GK"],
      "foot": "右",
      "tags": ["门线型"],
      "weak": "压迫下失误",
      "weakNote": "出球受压是分析观点；非官方统计，属于候选判断",
      "src": [
        "https://www.chelseafc.com/en/news/article/emiliano-martinez-signs-for-chelsea",
        "https://www.ea.com/zh-hans/games/ea-sports-fc/ratings/player-ratings/emiliano-martinez/202811"
      ],
      "conf": "待确认",
      "note": "官宣队籍；脚由 EA FC 27 交叉核对；弱点候选"
    }
  ]
}
```

`conf` 只能是 `已核实 / 待确认 / 冲突`。`src` 至少一个 `https://` URL。

## 来源规则

1. 俱乐部官网 / Premier League：队籍、位置
2. Transfermarkt：位置、脚、队籍
3. FotMob / EA FC：脚的第二来源
4. 媒体分析：只用于标签/弱点候选，不单独证明队籍

出现冲突（例如官网与 TM 的队籍不同）时：`conf: "冲突"`，在 `note` 写明两边来源，让用户决定。不要静默选择。

## 写入规则

1. 只写用户勾选的行；未勾选/冲突行不进库。
2. 先加 `players.js`，再跑校验器/构建；不要一次改多个层。
3. 需要固定首发时加 `PREFERRED`：
   - 3-4-2-1 示例：`['门将','右中卫','居中','左中卫','右翼卫','CM','CM','左翼卫','AM','AM','ST']`
   - 槽位顺序必须与 `FORMS[form]` 一致。
